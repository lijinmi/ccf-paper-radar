## 11-11 晚：范围收窄为 CV 视角（v0.2）

用户决策：**只收 CV 三大（CVPR/ICCV/ECCV）+ NeurIPS/ICLR/ICML 共 6 个会，不做 NLP**。理由是"主要为 CV 提供灵感"。
已被取代的方案：v0.1 的 11 会（含 ACL/EMNLP/NAACL/AAAI/IJCAI），已移入 venues.yaml 的 `dropped` 段保留记录。

关键新结论：
- **"CV 三大"每年只开两个**：ICCV 奇数年、ECCV 偶数年。2025 实际是 CVPR+ICCV+NeurIPS+ICLR+ICML 五个会。导航和数据同比分母都要按当年实际开的会算。
- 原始全量：2025 年 17,828 篇，2024 年 14,020 篇，两年 31,848 篇。
- **过 CV 相关性筛选后两年约 16,688 篇**，正好在 Cloudflare Pages 2 万文件上限内 → 两年可一次性全量发布，不用分片换托管。
- ML 三会 CV 相关占比估算：NeurIPS ~30%、ICLR ~32%、ICML ~22%（一年约 3,488 篇）。

核心产品设计（这是差异化所在）：
- 每篇 ML 论文必须输出 `cv_relevance`(high/medium/low) + `cv_angle`（一句具体的迁移方向）+ `evidence`（原文证据，防止编造）+ `related_cv_tasks`。
- 强制 evidence 字段是为了避免 cv_angle 变成"对视觉领域具有启发意义"这类废话。
- 判据：VLM/多模态要收（视觉是一半任务），纯文本 RAG 不收。
- 分类骨架以 CV 任务域为中心（L1 十个任务域）+ 方法族横切（L2）+ 自由标签（L3），另加 `venue_role`(主干/方法外溢)。

数据源实测（6 个会里 4 个抓不到）：
- CVF（CVPR/ICCV）🐢 200 但 20~25s，需 60s 超时
- PMLR（ICML）🐢 ~20s，需年份→卷号映射
- ECVA（ECCV）❌ 超时无响应
- proceedings.neurips.cc ❌ 超时 60s+，papers.nips.cc 也不通
- OpenReview api2 ❌ 403 `ChallengeRequiredError`（Cloudflare 人机验证）；openreview.net 网页 200 但数据靠 403 的 API
- dblp.org ❌ 202 挑战页
- ✅ arxiv.org 3.7s 可用 → 可作摘要兜底源

结论：抓取必须跑 GitHub Actions（海外 runner，免费）或香港服务器；ICLR 用 Playwright 或每年手动导出兜底。不要在自动化上死磕。

落地顺序：CVPR → ICCV（复用解析器）→ ICML → NeurIPS → ICLR → ECCV。第一周目标只做 CVPR 2025 全量。

成本：3.17 万篇分类 + 1.67 万篇翻译 ≈ ¥150。
